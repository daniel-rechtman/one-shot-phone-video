# seedance — ניסויים מקומיים עם Seedance דרך fal.ai

כלי CLI בקובץ אחד. **stdlib בלבד** — אין `pip install`, אין venv, אין תלויות.

## התקנה (פעם אחת)

קח מפתח מ-<https://fal.ai/dashboard/keys> ואז:

```bash
echo '{"FAL_KEY":"<המפתח-שלך>"}' > ~/.claude/secrets/fal.json
chmod 600 ~/.claude/secrets/fal.json
```

הכלי קורא את המפתח מ-`FAL_KEY` בסביבה, ואם אין — מ-`~/.claude/secrets/fal.json`.

## שימוש

```bash
./seedance.py cost --dur 8 --ar 9:16        # כמה יעלה, בלי לשלם כלום
./seedance.py t2v "פרומפט" --dur 5 --ar 9:16 --fast
./seedance.py i2v product.png "המצלמה מקיפה את המוצר" --dur 6
./seedance.py ref "@Image1 מחזיק את @Image2" -i face.png -i bottle.png
./seedance.py spend                          # מה הוצאתי עד עכשיו
./seedance.py get <request_id> --endpoint <ep>   # לשחזר job שנתקע
```

דגלים שחוזרים בכל פקודות הווידאו:
`--dur` (4-15 או auto) · `--res` (480p/720p/1080p/4k) · `--ar` · `--fast` ·
`--no-audio` · `--seed` · `--dry-run` · `-y` · `--open`

## שלוש הגנות על הכיס

הכלי הזה שורף כסף אמיתי בכל הרצה, אז:

1. **`--dry-run`** מדפיס את ה-payload ואת העלות בלי לשלוח כלום.
2. **אישור אוטומטי מעל $2.50** — הכלי עוצר ושואל. לשינוי: `SEEDANCE_CONFIRM_ABOVE=5 ./seedance.py …`, לדילוג: `-y`.
3. **`runs/ledger.jsonl`** — כל הרצה נרשמת פעמיים: ההערכה מראש, והעלות **שנמדדה
   בפועל** מממדי ה-MP4. `./seedance.py spend` מסכם, ו-`~` מסמן שורה שלא נמדדה.

אם הכלי נופל או אתה עושה Ctrl-C אחרי השליחה — ה-job ממשיך לרוץ בצד של fal ואתה
**כבר חויבת**. תמיד שחזר עם `get <request_id>` במקום להריץ מחדש. ה-`request_id`
נשמר ב-`runs/<timestamp>-<סוג>/request.json` מיד עם השליחה, לפני ההמתנה.

## תמחור — איך זה באמת עובד

fal מתמחר את Seedance **לפי טוקנים**, לא לפי שנייה:

```
tokens = (רוחב × גובה × שניות × 24) / 1024
standard = $0.014 / 1k tokens     fast = $0.0112 / 1k tokens
```

אימות: 1280×720 → 21,600 טוקנים לשנייה → $0.3024/שנייה, בדיוק המחיר המפורסם.

**אבל fal לא מפיק את הממדים הנומינליים.** נמדד בפועל: ביקשנו 480p ב-9:16 וקיבלנו
496×864 במקום 480×853 — כ-4.7% יותר פיקסלים, כלומר 4.7% יותר כסף. כלל העיגול שלהם
לא ידוע מדגימה אחת, אז ההערכה מראש כוללת **מרווח ביטחון של 10% והיא חסם עליון**.
העלות האמיתית נמדדת מה-MP4 עם `ffprobe` אחרי ההורדה ונרשמת ב-ledger.

המשמעות המעשית — **רזולוציה מכפילה עלות ריבועית**. 10 שניות ב-9:16 (חסם עליון):

| רזולוציה | standard | fast |
|---|---|---|
| 480p | $1.48 | $1.18 |
| 720p | $3.33 | $2.66 |
| 1080p | $7.48 | $5.99 |
| 4k | $29.93 | — |

**תנסה ב-480p, תפיק ב-720p/1080p.** אותו seed, אותו פרומפט — קודם תראה אם
הקומפוזיציה עובדת ב-13 סנט לשנייה ורק אז תשלם פי חמש.

`--fast` חוסך 20% ומוגבל ל-720p ומטה. האודיו כלול במחיר; `--no-audio` לא מוזיל.

## נקודות על המודל

- **`ref` הוא הסיבה שהמודל הזה מעניין.** עד 12 קבצי רפרנס בבקשה אחת (9 תמונות,
  3 וידאו, 3 אודיו) — ומפנים אליהם מתוך הפרומפט עם `@Image1`, `@Video1`, `@Audio1`.
  זה מה שנותן עקביות דמות בין שוטים בלי טריקי ה-last-frame שהפייפליין הנוכחי עושה.
  אודיו דורש לפחות תמונה או וידאו אחד.
- `--seed` עם אותו פרומפט = אותו פלט. ככה משווים שינוי אחד בפרומפט.
- `duration: auto` נותן למודל להחליט — ואז אי אפשר לדעת את העלות מראש.
  ההערכה מניחה 5 שניות. בניסויים תמיד תן מספר מפורש.
- `--model 2.5` קיים אבל **הסכמה שלו לא אומתה** — 2.0 הוא ברירת המחדל הבדוקה.
- **זמן:** קליפ של 5 שניות ב-480p לקח 218 שניות (3.5 דק') מקצה לקצה. אל תצפה
  לאיטרציה מהירה; תכנן כמה ניסויים במקביל במקום לשבת ולחכות לכל אחד.

## מה כבר נבדק בפועל

`ref` על H3 רץ מקצה לקצה ב-2026-09-22: character sheet אחד → 4K ‏2192×3824,
‏10.1 שניות, ‏37MB, ‏$1.62. **כולל העלאת קובץ מקומי** — מסלול ההעלאה עובד.

`t2v` רץ מקצה לקצה ב-2026-09-22: 480p ‏9:16 ‏5 שניות, seed 42 → 496×864, ‏5.1 שניות,
h264 + aac‏ 44.1kHz, ‏1.3MB, ‏$0.72. `i2v` ו-`ref` **טרם נבדקו מול ה-API** —
הסכמות שלהם מתועדות אבל מסלול ההעלאה של קבצים מקומיים לא הורץ.

## מבנה

```
seedance.py           הכלי
runs/ledger.jsonl     שורה לכל הרצה
runs/<ts>-<סוג>/      request.json · result.json · ה-MP4
```

## שני מנועים — והפער במחיר

`--engine seedance` (ברירת מחדל) או `--engine h3` (MiniMax Hailuo-03). שניהם על אותו
מפתח fal, ושניהם עושים ריפרנסים מרובים — עד 12 קבצים, 9 תמונות / 3 וידאו / 3 אודיו.

**הם מתומחרים במודלים שונים לגמרי:**

| | Seedance 2.0 | MiniMax H3 |
|---|---|---|
| מודל תמחור | לפי טוקנים (`w·h·s·24/1024`) | **שטוח לשנייה** |
| 10ש' באיכות בינונית | $3.02 (720p) | **$0.60** (768P) |
| 10ש' ב-4K | $27.21 | **$1.60** |
| רפרנסים | כלולים | 5 ראשונות חינם, $0.08 לכל נוספת |
| אודיו | `generate_audio` | סטריאו נייטיב, תמיד |

**H3 זול פי 5 עד פי 17 על אותה משימה.** אם התוצאה מספקת — אין סיבה להריץ Seedance ב-4K.

הבדלי סכמה שהכלי מטפל בהם אוטומטית: ב-H3 הרזולוציות באותיות גדולות
(`480P/768P/2K/4K`), `duration` הוא integer, `auto` נקרא `adaptive`,
והרפרנסים הם `reference_image_urls` ולא `image_urls`. H3 מצטט אותם בפרומפט
כ-`Image 1` ולא `@Image1`.

## דמויות קבועות

`characters/` מחזיקה תמונות רפרנס. **character sheet אחד עם כמה זוויות והבעות
עובד טוב יותר מכמה תמונות נפרדות** — זו תמונה אחת, כלומר גם בתוך ה-5 החינמיות.

```bash
./seedance.py ref "The toddler from Image 1 ..." -i characters/baby.jpg --engine h3 --dur 10 --res 4k
```

## Endpoints

```
minimax/h3/reference-to-video
minimax/h3/image-to-video
fal-ai/minimax/image-01            (תמונות, $0.01 ליחידה)
bytedance/seedance-2.0/text-to-video
bytedance/seedance-2.0/image-to-video
bytedance/seedance-2.0/reference-to-video
bytedance/seedance-2.0/fast/<אותם שלושה>
```
ללא תחילית `fal-ai/`. הקריאות עוברות ב-queue API‏ (`https://queue.fal.run`), כלומר
שליחה → polling → תוצאה, מה שמחזיק גם הרצות ארוכות.
